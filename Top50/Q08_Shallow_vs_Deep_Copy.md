# Q08 Shallow vs Deep Copy

**Interview Answer:**
Shallow Copy and Deep Copy describe how an object’s data members are copied when a new object is created from an existing one — especially when the class contains pointers or dynamically allocated memory.

1. Shallow Copy
Copies the values of all member variables.

For pointers, it copies the address, not the memory they point to.

Both the original and the copy point to the same memory location.

Changes made through one object affect the other.

The default copy constructor generated by the compiler performs a shallow copy.

Problem: If one object is destroyed, it frees the memory, leaving the other with a dangling pointer. If both try to free, you get a double-free error.

Code Example (Shallow Copy Problem):

cpp
class Student {
    int* rollNo;
public:
    Student(int r) {
        rollNo = new int(r);
    }
    // Default copy constructor does shallow copy
    ~Student() { delete rollNo; }
};

int main() {
    Student s1(101);
    Student s2 = s1;   // Shallow copy: both point to same int
    // When s2 goes out of scope, it deletes rollNo.
    // s1's rollNo becomes dangling.
}
2. Deep Copy
Copies all fields and allocates new memory for pointers.

Copies the actual data pointed to, not just the address.

The original and the copy are completely independent.

Requires a user-defined copy constructor (and usually copy assignment operator and destructor — Rule of Three).

Needed whenever a class manages resources like dynamic memory, file handles, network connections, etc.

Code Example (Deep Copy Solution):

cpp
class Student {
    int* rollNo;
public:
    Student(int r) {
        rollNo = new int(r);
    }
    // Deep copy constructor
    Student(const Student& s) {
        rollNo = new int(*(s.rollNo));  // allocate new memory and copy value
    }
    ~Student() { delete rollNo; }
};

int main() {
    Student s1(101);
    Student s2 = s1;   // Deep copy: independent memory
    // Both have separate rollNo. No double-free.
}

Key Differences Table
Feature	Shallow Copy	Deep Copy
Pointer handling	Copies address	Allocates new memory, copies data
Independence	Objects share memory	Objects are independent
Default behavior	Compiler-generated copy constructor	Must be user-defined
Risk	Dangling pointer, double-free	Safe, but slower and uses more memory
When needed	Simple classes without pointers	Classes with dynamic memory/resources
Summary to Impress
Shallow copy copies pointer addresses → shared memory → dangerous.

Deep copy allocates new memory → independent objects → safe.

Default copy constructor is shallow; for classes with pointers, always write a deep copy constructor.

Follow Rule of Three: if you need a custom destructor, copy constructor, or copy assignment operator, define all three.

Deep copy prevents dangling pointers, double-free errors, and unintended side effects.
